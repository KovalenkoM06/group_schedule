# Лабораторна робота №1 — Розклад занять групи (Варіант 4)

Проєкт з дисципліни «Програмування мовою Dart» (варіант 4, номер у списку збірної групи — 19: `19 % 15 = 4`).
Предметна область: **Розклад занять групи** (`дисципліна, викладач, тип, день тижня, час початку, аудиторія`, а також числові поля тривалості заняття у хвилинах та оцінки/рейтингу курсу).

## Структура програми

Проєкт створено командою `dart create -t console group_schedule`:
- `lib/group_schedule.dart` — містить константи, оголошення типів через `Record`, вхідний список рядків, функції розбору, валідації, конвеєри обробки колекцій, замикання, регулярний вираз і побудову звіту. Логіку винесено в `lib/`, щоб її можна було імпортувати окремо від точки входу.
- `bin/group_schedule.dart` — точка входу `main()`, яка запускає обробку розкладу та виводить результати в консоль.

## Вибір типів даних

За умовою лабораторної роботи №1 класи не використовуються, тому обрано такі засоби мови:
- **`Record` (`typedef Lesson`, `typedef ParseResult`)** — використовується для зберігання полів одного заняття та результату парсингу рядка. Запис зручний тим, що має типізовані іменовані поля й не потребує створення класу.
- **`List<String>` та `List<Lesson>`** — для збереження вхідних CSV-рядків і впорядкованого списку занять, де важливий порядок елементів і сортування.
- **`Set<String>` (`allowedLessonTypes`)** — для переліку дозволених типів занять (`Лекція`, `Лабораторна`, `Практична`, `Консультація`), бо в множині перевірка `contains` працює найшвидше і немає дублікатів.
- **`Map<String, List<Lesson>>`** — для групування занять за днем тижня у функції `groupByDay`.
- **`DateTime` і `Duration`** — для збереження часу початку заняття та підрахунку віку запису в днях через `difference`.
- **`StringBuffer`** — для складання тексту звіту у функції `buildReport` замість конкатенації через `+=` у циклі.

## Обґрунтування щодо `!`, `late` та `dynamic`

У коді лабораторної роботи **не використано жодного оператора `!`, ключового слова `late` або типу `dynamic`**:
- Замість оператора `!` всюди використовуються локальні `final`-змінні та перевірки `if (value == null)`, після яких компілятор автоматично застосовує промоцію типів (type promotion). Для іменованих груп регулярного виразу (`namedGroup`) використано оператор `??`.
- Ключове слово `late` не знадобилося, оскільки всі змінні та константи отримують значення одразу при оголошенні.
- Тип `dynamic` не використовується, бо всі типи даних і параметри функцій відомі під час компіляції.

## Використані пакети з `pub.dev`

Зовнішні бібліотеки в розділі `dependencies` не підключалися — уся робота з рядками, датами й колекціями (зокрема `firstOrNull`, доступний у `dart:core` з Dart 3.0) виконана стандартними засобами Dart SDK.

У розділі `dev_dependencies` залишено лише один пакет:
- **`lints` (`^6.0.0`)** — офіційний набір правил статичного аналізатора від команди Dart (`package:lints/recommended.yaml`), який потрібен для перевірки коду командою `dart analyze`. Як альтернативи розглядалися `very_good_analysis` або ручне прописування всіх правил у `analysis_options.yaml`, але `lints` є стандартним рекомендованим пакетом у методичних вказівках і не містить зайвих залежностей.
